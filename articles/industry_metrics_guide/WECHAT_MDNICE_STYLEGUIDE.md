# 微信公众号与墨滴 (mdnice) 排版排坑避雷指南
## 专栏官方排版规范与 Markdown 语法免死金牌手册（买方投研专栏专属）

---

> **核心原则**：微信公众号富文本编辑器及其前端生态（以墨滴 mdnice 为代表）底层的 Markdown 解析器基于特定的 JavaScript 编译器（如定制版 `marked.js`），其对**中英文混排、数学符号以及标点符号的边界定界符（Delimiter Run）**有极其严苛甚至存在 Bug 的判定逻辑。
> 一旦触碰底层的“标点冲突”或“HTML标签歧义”，就会导致**加粗失效露出星号 `**`、文字被吞、公式乱码、表格溢出**等严重排版事故。
> 
> 本指南系统汇总专栏在实战排版中总结出的**全部避雷军规与免死写法**，供人类作者与 AI 自动化排版时严格共同遵守。

---

## 📌 一、 加粗语法 (`**`) 避坑四大军规

Markdown 标准规范规定，开启与闭合粗体的 `**` 必须符合“合法定界符（Flanking Delimiter Run）”规则。当 `**` 紧贴特殊标点时，解析器极易判定失败。

### 军规 1【列表小标题冒号内包】：冒号统一放进加粗内，后留半角空格
* ❌ **致命写法**：`* **门槛收益率 (Hurdle Rate)**: 正文`（双标点夹击 `)**:`，墨滴必死）
* ❌ **致命写法**：`* **门槛收益率 (Hurdle Rate)**：正文`（双标点夹击 `)**：`，墨滴必死）
* ✅ **免死写法**：`* **门槛收益率 (Hurdle Rate)：** 正文`（冒号在内，加粗后有空格）
> **底层原理**：当 `**` 内侧是右括号 `)`（标点）、外侧是冒号 `:`（标点）时，形成“双标点夹击”，解析器无法判定边界；将冒号包进加粗内后，`**` 后面是**空格**，所有 Markdown 解析器 100% 能够识别加粗闭合！且出版界标准也是冒号连同小标题一起加粗，视觉更规整。

---

### 军规 2【数学与比较符号绝对外置】：符号在外，数字在内
* ❌ **致命写法**：`**≥ 4.0% ~ 5.0%**`（`**` 紧挨 `≥`，判定为非法起始符号）
* ❌ **致命写法**：`**< 1.0%**`（`<` 会被解析器当作 HTML 标签起始，导致样式崩溃或文字被吞）
* ❌ **致命写法**：`**10.95% ≈ 11.0%**`（加粗内包含约等于号，且两边带数值容易触发解析混乱）
* ✅ **免死写法**：`≥ **4.0% ~ 5.0%**`
* ✅ **免死写法**：`< **1.0%** 或为负数`
* ✅ **免死写法**：`＝ **10.95%** ≈ **11.0%**`
> **底层原理**：让比较符号（`≥`、`≤`、`<`、`>`、`≈`）作为普通文本，加粗内部只保留纯阿拉伯数字。`**` 两侧直接紧挨数字，解析器 100% 能够正确渲染粗体。

---

### 军规 3【加粗紧贴中文句号/分号时：显式加半角空格】
* ❌ **致命写法**：`年化有机费率增速达到 **11.0%**。`（`%**。` 双标点粘连，有时暴露星号）
* ❌ **致命写法**：`提取超出部分利润的 **20%**；`（`%**；` 双标点粘连，必死）
* ✅ **免死写法**：`年化有机费率增速达到 **11.0%** 。`（在 `**` 和句号之间加一个半角空格）
* ✅ **免死写法**：`提取超出部分利润的 **20%** 提成；`（在加粗后跟汉字，彻底化解标点）
* ✅ **免死写法**：`提取超出部分利润的 **20%** ；`（在加粗和分号之间加一个半角空格）

---

### 军规 4【加粗紧贴中文/英文括号时：显式加半角空格】
* ❌ **致命写法**：`净新增资金达 **$2,050 亿美元**（其中 iShares 贡献...）`
* ❌ **致命写法**：`年化有机净流入率 ≥ **4.0% ~ 5.0%**（连续跨周期达标...）`
* ✅ **免死写法**：`净新增资金达 **$2,050 亿美元** （其中 iShares 贡献...）`
* ✅ **免死写法**：`年化有机净流入率 ≥ **4.0% ~ 5.0%** （连续跨周期达标...）`
> **底层原理**：加粗结束的 `**` 紧贴全角左括号 `（` 时，缺乏空白分隔，解析器会认为括号是单词的一部分而拒绝闭合加粗。在加粗与括号之间留一个半角空格，完美避开所有解析 Bug。

## 📌 二、 数学公式与财务符号规范

1. **绝对禁用 LaTeX 原生语法**：
   * 严禁出现 `$...$` 或 `$$...$$` 语法（微信公众平台后台完全不支持原生 LaTeX，会直接显示未渲染的代码）。
2. **全面采用标准 Unicode 数学字符**：
   * 等号：`＝`（全角）或 `=`（半角留空格）
   * 乘除法：`×`、`÷`
   * 加减法：`＋`、`−`
   * 比较符：`≥`、`≤`、`≈`、`≠`
   * 变动与逻辑：`Δ`、`→`、`±`、`∑`
3. **消除会计负数歧义**：
   * 避免使用华尔街财报中的单边美元符括号，如 `$(30) 亿`（容易引发公式解析混淆）；
   * 规范写为：`-$30 亿` 或 `亏损 $30 亿`。
4. **杜绝双 `$` 误触 LaTeX 与 `%` 吞字灾难（正文一律规范使用「亿美元」）**：
   * **底层灾难原理**：在 Markdown / 墨滴中，半角 `$` 是行内公式触发符。若同一段落出现两个 `$` 且中间带有百分号 `%`（如 `$3,000 亿... 40%... $1,200 亿`），墨滴会将双 `$` 之间误判为 LaTeX 公式，并将 `%` 之后的文字当作注释代码彻底吞掉删除！且转义符 `\$` 在墨滴中往往无法稳定规避。
   * **彻底免死铁律**：正文叙述中**严禁混用一对 `$` 与 `%`**，一律规范写为 **`3,000 亿美元`**、**`1,200 亿美元`**，不仅符合中文高级财经语感，而且 100% 免疫任何公式误触与吞字 Bug。

## 📌 三、 表格跨端自适应与墨滴排版规范

### 1. 双标的跨周期对比数据在单元格内的排版
* **用户与微信阅读首选标准**：两家公司数据统一放入**同一个单元格内**，用 `<br>` 上下紧凑换行对比：
  ```markdown
  | **总资产规模 (AUM)** | **BLK**<br>BX | **$10.01 万亿**<br>$8,809 亿 | **$15.49 万亿**<br>**$1.38 万亿** |
  ```
* **严禁单独拆分成空行**：严禁在对比的两行数据之间多打一个回车或留空。

### 2. 墨滴消除表格多余行高通用 CSS 配置
在墨滴 (mdnice) 的“自定义 CSS”中注入以下两行代码，即可永久消除表格内 `<br>` 导致的多余空行问题：
```css
/* 墨滴表格通用紧凑排版优化 */
table td {
  line-height: 1.25 !important;
  vertical-align: middle !important;
}

table td br {
  display: inline !important;
  margin: 0 !important;
  padding: 0 !important;
}
```


```css
/* 开启表格在手机端的横向丝滑滑动，杜绝文字竖排挤压 */
.table-container,
table {
  display: block !important;
  width: 100% !important;
  overflow-x: auto !important;
  -webkit-overflow-scrolling: touch !important;
  white-space: nowrap !important;
  word-break: keep-all !important;
}

/* 单元格保持舒适的内边距与字体 */
table th, table td {
  padding: 8px 12px !important;
  white-space: nowrap !important;
  font-size: 13px !important;
}
```

### 3. 表格宽度安全底线
* 严禁在 `<td>` 标签上强制加 `max-width`，这会导致粘贴进微信公众号后台时原生编辑器闪退崩溃。

## 📌 四、 引用块与页面排版结构红线

1. **微信引用块 (Blockquote) 单块 300 汉字绝对红线**：
   * 微信公众平台严格限制：**单个 `<blockquote>`（即 `>`）引述内容绝对不得超过 300 汉字**，超出在发布时会直接报错；
   * 正文中的案例分析、分析段落绝不使用 `>` 包裹；
   * `>` 仅用于：文首“一句话买方导读”（100 字内）、走势图“买方核心解读”（200 字内）、文末“买方终极心法”（100 字内）。
2. **严禁 Mermaid JS 与 ASCII 字符代码块**：
   * 微信后台不支持 Mermaid 图表脚本，会直接暴露丑陋源码；
   * 严禁使用 ````text ┌─── ```` 这类 ASCII 边框代码块；
   * 矩阵和架构一律用标准 Markdown 表格排版，自查表一律用“步骤卡片流 ＋ 🟢/🟡/🔴 指示灯 ＋ 行内代码块反引号”进行高保真排版。

## 📌 六、 视觉节奏与“按需排版”黄金准则（点、线、面、块的平衡艺术）

文字排版的本质是**节奏感（Rhythm & Contrast）**。既不能“万物皆套小圆圈”（造成清单式审美疲劳），也不能“一刀切全部纯文本”（导致白开水般的扁平无层级）。必须坚持**“按需点缀、克制平衡”**。

### 1. 文首“双卡片独立分立”规范
* **原则：** 专栏元数据（定位、标的、指标）与买方导读是两个不同性质的维度。
* **写法：** 两个 `>` 引用块之间**必须留纯空行彻底断开**，严禁使用空的 `>` 行粘连：
  ```markdown
  > **专栏定位：** 全行业 10-K/10-Q 外科手术显微镜与非 GAAP 核心指标全景字典  
  > **解剖标的：** 摩根大通 (JPM) 深度穿透 ＋ 美国银行 (BAC) 镜像对照  
  > **核心指标：** 净利息收入 (NII)、净息差 (NIM)、ROTCE、CET1、拨备 (Provision)

  > **买方导读：** 商业银行没有实体企业的毛利率与自由现金流（FCF），它是一台将储户存款作为“负债原材料”...
  ```
* **效果：** 在墨滴中生成两个清爽独立的主题色边框卡片（一张信息卡，一张导读卡），极富杂志出版质感。

---

### 2. 精确计算公式的“单行闭环与代码块规范”
* **原则：** 公式是金融量化分析的灵魂算子，应当精炼、对称、**单行完整闭环**。
* **标准范式：**
  ```markdown
  #### 2. 精确计算公式
  `净息差 (NIM) ＝ 年化净利息收入 (FTE NII) ÷ 平均生息资产余额 × 100%`  
  `净利差 (NIS) ＝ 生息资产平均收益率 (Yield) − 付息负债平均成本率 (Rate)`
  **其中：**
  * `生息资产平均收益率 (Yield) ＝ 利息总收入 (FTE) ÷ 平均生息资产总额`
  * `付息负债平均成本率 (Rate) ＝ 利息总支出 ÷ 平均付息负债总额`

  **买方核心勾稽（利差剪刀差）：**  
  只要银行拥有“非付息核心存款（无成本支票账户）”或“自有股东权益资金”支撑生息资产，`NIM` 必然永远高于 `NIS`。两者之间的剪刀差，反映了银行利用“零成本无息负债”放大息差杠杆的核心护城河。

  **报表定位：** SEC 10-K / 10-Q 之 MD&A 章节「平均资产负债表与利差分析 (Average Balance Sheets)」专表。
  ```
* **四大免死铁律：**
  1. **主公式直接置顶**：核心公式紧随小标题独占一行，使用行内代码块包裹，利用等宽字体和浅灰底色胶囊凸显算子地位；
  2. **公式内英文的专业平衡**：中文后保留必要英文简称或全称以保证专业信披准确；即便因包含完整英文而在手机端自然折行亦完全合适，无需为避免折行而过度牺牲专业要素；
  3. **辅助算子对仗归组**：用 `**其中：**` 引领子算式，保持列表体量严格对仗；
  4. **商业逻辑独立成段**：长篇商业洞察与剪刀差逻辑**严禁混入公式列表**，必须作为独立加粗段落舒展展开。

---

### 3. 列表小圆圈 (`* `) 的“并列抓手与零嵌套原则”
* **必须用圆圈的地方：**
  * **时间线对账点**（如 `* 2021 年低谷核算：...`、`* 2025 年报核算：...`、`* 2026 Q3 最新对账：...`），圆圈提供极强的条理抓手；
  * **对仗的分项对比**（如 `* 利息总收入（资产端引擎）：...` vs `* 利息总支出（负债端成本）：...`）；
  * **辅助算子拆解**（如 `* 生息资产平均收益率...` vs `* 付息负债平均成本率...`）。
* **绝不用圆圈的地方：**
  * 核心计算公式行；
  * 长篇分析推演段落；
  * 报表定位（单行平实收尾）。
* **结构红线：** **绝对严禁二级缩进嵌套列表**（即禁止在 `*` 内部再打 `  *`），所有列表必须保持一层扁平。

---

### 4. 行内代码块 (`...`) 的“防灰斑克制准则”
* **按需精准点缀（少而精）：**
  * ✅ 核心计算公式与模型方程：如 `` `P / TBV ＝ (ROTCE − g) ÷ (COE − g)` ``；
  * ✅ 自查卡中的量化判定条件：如 `` `CET1 ≥ 14.5%` ``、`` `ROTCE ≥ 18.0%` ``、`` `> 2.0x P/TBV` ``；
  * ✅ 核心变量对比：如正文中的 `` `NIM` `` 与 `` `NIS` ``。
* **严禁滥用：** 严禁把普通英文单词、报表章节名、普通指标随手套反引号，杜绝页面产生“灰底麻子点”式的视觉杂乱。

---

### 5. 功能性 Emoji 的“仪表盘限定准则”
* **唯一允许使用的 Emoji：** 自查排查卡中的等级指示灯：
  * 🟢 **优异安全**
  * 🟡 **中规中矩**
  * 🔴 **高危预警**
* **彻底清退装饰性表情：** 正文、标题、步骤卡片一律禁用 📐、📍、📌、💡、👉、🔥、🚀 等装饰符号，保持买方机构研报的严肃与高级感。

### 6. 列表标签与解释的“换行缩进准则”（解决移动端犬牙交错）
* **核心痛点：** 在微信移动端窄屏（375px~430px）下，当列表的前置粗体标签较长（如超过 10 个字或带有英文缩写/括号）时，若解释紧随冒号不换行，第一行只能挤下几个字，导致正文右侧悬空、整体排版犬牙交错。
* **两大分类处理法：**
  1. **长标签（> 10 字或含英文括号/业务定语）或多行深度解释：必须换行！**
     * **范式：** 粗体标题行尾加两个半角空格 `  `，下一行缩进 2 个空格 `  ` 承接正文；
     * **视觉收益：** 粗体标题在圆点旁充当清晰有力的“迷你分类标签（Tag）”，正文在下方独立成块、整齐舒展展开，读者扫读标签即可瞬间抓住分项脉络。
     * **示范代码：**
       ```markdown
       * **传统重资产做市型投行（以交易/承销为主导）：**  
         盈利跟随金融周期剧烈起伏，市场给予其较高的风险溢价（`COE ≥ 11%~12%`），历史平均 ROTCE 中枢仅 12%~14%，二级市场公允倍数长期锁定在 `1.2x ~ 1.5x P/TBV`；
       * **轻资产财富管理型现代投行（以经常性资管为主导）：**  
         经常性管理费提供高确定性底盘，盈利波动率骤降，市场要求的回报率降低（`COE 降至 9%`），长期可持续 ROTCE 稳定在 `18% ~ 22%`，公允倍数被重估至 `2.2x ~ 2.6x P/TBV`。
       ```
  2. **短标签（≤ 8 字）且为单行简短事实：保持同行不换行**
     * 避免短小标签换行导致纵向过度拉伸。
     * **示范代码：**
       ```markdown
       * **法定合格线：** 美联储设立的法定最低合格标准为 `5.0%`；
       * **买方安全垫：** 投行日常必须保持在 `5.3% ~ 5.6% 以上` 的安全防线。
       ```
